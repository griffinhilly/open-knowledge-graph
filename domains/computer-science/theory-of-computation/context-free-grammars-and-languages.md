# Context-Free Grammars and Languages

## Core Idea
A context-free grammar (CFG) is a set of production rules of the form A → α, where A is a non-terminal and α is a string of terminals and non-terminals. CFGs generate context-free languages and are used to define the syntax of programming languages, arithmetic expressions, and structured text.

## Explainer

You have seen that finite automata and regular expressions cannot handle certain patterns — notably, anything requiring matched nesting, like balanced parentheses or the language aⁿbⁿ. That limitation of finite automata is exactly what motivates context-free grammars. A **context-free grammar** is a more powerful way to specify a language, using **production rules** that let you replace a single non-terminal symbol with any sequence of terminals and non-terminals. The key word is "context-free": when you apply a rule A → α, you can replace A regardless of what symbols surround it. The replacement depends only on A itself, not on its context in the string.

A CFG has four components: a set of **terminal symbols** (the actual characters that appear in the language's strings), a set of **non-terminal symbols** (variables that represent structural categories), a set of **production rules** (rewriting instructions), and a designated **start symbol**. To generate a string, you begin with the start symbol and repeatedly apply productions — replacing non-terminals with the right-hand side of a matching rule — until only terminals remain. For example, to define balanced parentheses, you might write: S → (S) | SS | ε. Starting from S, you can derive "()", "(())", "()()", and any other balanced string, but never ")(" or "(()" — the grammar's structure enforces the matching.

The reason CFGs matter so deeply in computer science is that they capture **recursive syntactic structure**. An arithmetic expression is either a number, or an expression plus an expression, or an expression times an expression — the definition refers back to itself. A CFG models this naturally: E → E + E | E * E | (E) | number. This is why virtually every programming language's syntax is defined by a context-free grammar. When you write code and your editor highlights a syntax error, a parser built from a CFG (or a close variant) has determined that your code cannot be derived from the language's grammar.

The language generated by a CFG — the set of all terminal strings derivable from the start symbol — is called a **context-free language (CFL)**. CFLs are strictly more powerful than regular languages: every regular language can also be generated by a CFG, but languages like aⁿbⁿ and balanced parentheses are context-free but not regular. However, CFLs have their own limits. The language aⁿbⁿcⁿ (requiring three groups to match in count) is *not* context-free — a fact provable via the pumping lemma for context-free languages. Understanding what CFGs can and cannot express is essential groundwork for parsing theory, compiler design, and the broader Chomsky hierarchy.
