## Flags

- optimization-theory-for-ml.md, Q0 explanation: "1/sqrt(C) < n/C when C > n^2". The inequality is reversed: 1/sqrt(C) < n/C holds when C < n^2. The sentence then contradicts itself ("For moderate budgets, SGD is dramatically better").
- optimization-theory-for-ml.md, Q1 explanation: "The Robbins-Monro conditions ... are necessary and sufficient for SGD to converge". They are standard sufficient conditions. Necessity does not hold in general.
- optimization-theory-for-ml.md, Q3 answer: "cannot extract more than O(sqrt(T)) bits of useful information". This is not a standard or precise statement of the lower bound.
- optimization-theory-for-ml.md, Explainer: "the noise in SGD has been shown to have beneficial regularization effects". This is an active hypothesis with mixed evidence, stated as settled.
- overparameterization-theory.md, Q1: the keyed answer "volume of good solutions ... easier for SGD to find through random search" is weak. SGD is not random search, and the explanation is speculative.
- overparameterization-theory.md, Q3: the keyed answer says a higher learning rate is NOT implicit regularization. Large learning rates are widely argued to act as implicit regularization (bias toward flatter minima). The item is contestable.
- overparameterization-theory.md, Explainer: "classical learning theory, which predicts monotonic increase in test error with model complexity". The classical picture is U-shaped, not monotonic. Also "nearly every direction of gradient descent encounters solutions that ... generalize" overclaims.
- pac-learning-framework.md, Q3 (true-false, answer false): whether "PAC-learnable" requires polynomial time depends on convention. Many texts define PAC-learnable statistically and use "efficiently PAC-learnable" for the time condition. The file's own Explainer uses "information-theoretically learnable".
- pac-learning-framework.md, Explainer: "general Boolean functions ... are provably not [learnable] under standard complexity assumptions". General Boolean functions fail for information-theoretic reasons (VC dimension 2^n), no complexity assumption needed.
- rademacher-complexity.md, Q2 (true-false, answer true): "The empirical Rademacher complexity ... always decreases as the sample size increases" is false. Counterexample: H = {h1, h2} that agree on x1 and differ on x2. On {x1} the value is 0. On {x1, x2} it is 1/2.
- rademacher-complexity.md, Explainer: the bound "R_hat(h) + 2 R_S(H) + sqrt(log(1/delta)/(2n))" mixes versions. With the empirical complexity R_S the confidence term is about 3 sqrt(log(2/delta)/(2n)). The sqrt(log(1/delta)/(2n)) form goes with the expected complexity. Also, "explains why deep networks with millions of parameters can generalize well" overclaims.
- regularization-theory.md, Q0 explanation: "alpha_i = sigma_i / (sigma_i^2 + lambda) * (u_i^T y) / sigma_i = 1/(sigma_i + lambda) * (u_i^T y)". The algebra is wrong as written: the two sides are not equal.
- representer-theorem.md, Q3 answer and Explainer: the objective uses (1/n) sum of losses + lambda ||f||^2, but the closed form is given as alpha = (K + lambda I)^{-1} y. With the 1/n scaling it is (K + n lambda I)^{-1} y.
- sample-complexity-bounds.md, Core Idea and Explainer: the realizable sample complexity is given as Theta((d/epsilon) log(1/epsilon) + ...), and the Explainer says the log(1/epsilon) factor "is known to be tight". The optimal realizable sample complexity is Theta((d + log(1/delta))/epsilon) (Hanneke 2016). The log factor is tight only for some ERM learners, not for the best learner.
- sample-complexity-bounds.md, Q0: the keyed option says "About 20,000 samples", but the explanation computes about 9,500.
- self-supervised-learning-theory.md, Core Idea and Explainer: "predicting masked tokens in language (BERT, GPT)" and "Masked Prediction (BERT, GPT, MAE)". GPT uses next-token (autoregressive) prediction, not masked prediction.
- self-supervised-learning-theory.md, Explainer: "Momentum-based (MoCo, BYOL) ... efficient contrastive learning with fewer negatives". BYOL uses no negatives at all.
- self-supervised-learning-theory.md, Q2: states as settled that compression explains SSL. The information-bottleneck account of SSL is contested.
- self-supervised-learning-theory.md, Q3: typed true-false but the stem is a "what is the difference" question, so it has no true/false answer.
- structural-risk-minimization.md, Q2 (true-false, answer true): "With unlimited data SRM would always select the most complex class" is not correct. An infinite hierarchy has no most complex class. If a smaller class already contains the target, the penalty favors that smaller class.
- structural-risk-minimization.md, Explainer last sentence: "model selection criteria like the Structural Risk Minimization principle underlying SVMs" is circular and garbled.
- transformer-theory-attention.md, Explainer, Permutation Equivariance: "Self-attention respects the ordering of inputs ... This ensures the model leverages sequential structure." Wrong. Equivariance means self-attention ignores order, which is why positional encodings are needed (the file's own Positional Encoding paragraph says so).
- transformer-theory-attention.md, Q3: typed true-false but the stem asks "why", so it has no true/false answer. It also states "remained largely unchanged since 2017" as fact.
- transformer-theory-attention.md, Explainer: "Universal Approximation ... a stronger result than MLPs" and "Weight decay ... bias solutions toward sparse, interpretable attention patterns" are unsupported.
- uniform-convergence-bounds.md, Q4 answer: "union bound over Pi_H(n) hypotheses gives P(any gap > epsilon) <= Pi_H(n) * exp(-2n epsilon^2)". This skips the symmetrization (ghost sample) step. The true risk is not set by the labelings on the sample, so the real bound uses Pi_H(2n) with different constants.
- uniform-convergence-bounds.md, Q1: the keyed option says about 4,000 samples, but the explanation computes about 5,200, and constants are ignored.
- vc-dimension-theory.md, Q4: "shatters a set of 10 points but fails to shatter some set of 11 points" gives "Exactly 10" as the answer. This is wrong. Failing on one 11-point set does not bound the VC dimension. The correct conclusion is "at least 10", which is not an option. My new misconception bullet states the correct rule, so it contradicts this item's explanation. The item needs a rewrite.
- vc-dimension-theory.md, Core Idea vs Explainer: Core says sample complexity O(d/epsilon). The Explainer says Theta((d + log(1/delta))/epsilon^2) "for PAC learning". These are the realizable and agnostic rates, mixed without labels. Q0's keyed option (d log(1/epsilon) + log(1/delta))/epsilon^2 matches neither standard form.
- vc-dimension-theory.md, Explainer: "neural networks with w weights have VC dimension O(w^2) to O(w^4)". Threshold and ReLU networks have near-linear bounds (about w log w, or w L log w with depth). O(w^4) is the sigmoid upper bound. Also "regularization ... reduces the VC dimension ... by constraining parameter magnitudes" is wrong for sign classifiers: norm bounds do not change VC dimension (scale invariance), they reduce margin-based capacity. "Covering numbers and epsilon-nets, which measure how finely the input space must be discretized" is also inaccurate.
- vc-dimension.md, Explainer: "O((d/epsilon) log(1/epsilon) + ...) ... This is a tight characterization". Same issue as sample-complexity-bounds: the optimal realizable rate drops the log(1/epsilon) factor.
