## Flags

### Suspected factual errors in existing text
- single-cycle-processor-design.md, Q4 (true-false): "reducing the number of instructions in a program directly reduces execution time, regardless of which instruction types are used" is marked `false`. On a fixed single-cycle design, time = instruction count × fixed clock period (CPI = 1), so fewer instructions always means less time. The explanation itself says "the clock period doesn't change." The answer should be `true`, or the question should be reworded.
- single-cycle-processor-design.md, Explainer and Q5 explanation: the multi-cycle design is described as breaking execution into "variable-length steps" / "variable-length phases". Multi-cycle uses fixed short cycles and a variable number of them per instruction.
- single-cycle-processor-design.md, Q5 answer: "the entire datapath is combinational". The PC and register file are clocked state elements; the paths between them are combinational.
- static-ram-sram-design.md, Core Idea: "An SRAM cell is a cross-coupled NOR or NAND latch". The standard 6T cell, as the file's own Explainer says, is two cross-coupled inverters plus two access transistors.
- static-ram-sram-design.md, Core Idea / Explainer: "single-cycle access" for SRAM in general. Large SRAM caches (L2, L3) take many cycles to access.
- static-ram-sram-design.md, Q4 explanation: "SRAM is never used for main memory". Many microcontrollers and embedded systems use on-chip SRAM as their main memory.
- static-ram-sram-design.md, Q1 explanation: "6× area penalty". The cell-area ratio between 6T SRAM and 1T1C DRAM is not simply 6 to 1; the transistor-count ratio is a rough proxy.
- processor-status-flags-and-conditions.md, Explainer: "This two-step pattern ... is how processors implement every if-statement". MIPS and RISC-V have no condition flags and use compare-and-branch instructions instead.
- processor-status-flags-and-conditions.md, Explainer paragraph 1: "single-bit indicators that the ALU sets automatically as a side effect of each operation" contradicts the file's own last paragraph (ARM sets flags only with the S suffix).
- processor-control-unit-design.md, Q4: "present a hardwired interface to software" does not have a clear meaning. Also, modern x86 decodes most instructions into micro-ops with hardware decoders; the microcode ROM handles mainly complex instructions.
- translation-lookaside-buffer-tlb.md, Q5 answer: "Data caches ... operate on physical addresses. Before any cache lookup can happen, the virtual address must be translated." Many L1 caches are virtually indexed, physically tagged, so the TLB lookup overlaps the cache index step.
- translation-lookaside-buffer-tlb.md, Q3 premise "Because the TLB is fully associative" while the Explainer says TLBs are fully associative or set-associative.
- translation-lookaside-buffer-tlb.md, Explainer: "the TLB is the single most performance-critical structure in the memory hierarchy" is an overclaim. Core Idea "typical sizes are 32–512 entries" understates modern second-level TLBs, which often have over 1,000 entries.
- sign-magnitude-encoding.md, Explainer: "Its main historical use is in the mantissa (significand) of IEEE 754". IEEE 754 is a current use, not a historical one.
- ripple-carry-adder-design.md, Q1 explanation: "The result 1000 is a valid 4-bit value, so there is no overflow." True for unsigned; for 4-bit two's complement, 0111 + 0001 = 1000 is signed overflow (7 + 1 = −8). The question does not say which.
- synchronous-logic-and-clocks.md, Q3 explanation: "Clock skew is a problem, not a feature." Intentional (useful) skew is a real timing-optimization technique; the true-false answer is defensible, but the explanation is absolute.
