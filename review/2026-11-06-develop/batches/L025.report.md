## Flags

### Suspected factual errors in existing text
- zero-knowledge-proofs-advanced.md, Core Idea: "zero-knowledge arguments (weaker soundness, allowing polynomial-time provers to cheat)". This is backwards. Arguments are sound against polynomial-time provers; only unbounded provers may cheat. The file's own Explainer states it correctly, so the two sections contradict each other.
- zero-knowledge-proofs-advanced.md, Q0 answer: "statistical soundness ... This requires multiple rounds of interaction" and "unconditional soundness requires interaction". NIZK proofs with statistical or perfect soundness exist in the CRS model, so this is too strong.
- zero-knowledge-proofs-advanced.md, Q2: a "What is the difference..." question has type true-false with answer true. The question is not a true/false statement.
- zero-knowledge-proofs-advanced.md, Q1 option 0: "the proof is shorter than the statement being proven". Succinctness is usually defined as sublinear in the witness or computation size, not the statement size.
- secure-multi-party-computation.md, Explainer: indistinguishability "automatically captures every conceivable security property (privacy, correctness, input independence, fairness)". Fairness cannot be achieved in general without an honest majority, and the standard dishonest-majority definitions give security with abort.
- secure-multi-party-computation.md, Q0 answer: Hospital A "learns nothing more specific about B or C individually" after learning that the combined B and C average is below 80. With an equal-weight average of 75 and A at 80, A can compute the exact B and C combined average (72.5), which is more than "lower than 80".
- secure-multi-party-computation.md, Core Idea: "with honest majority, information-theoretic security is achievable (BGW protocol)". For malicious adversaries, BGW's perfect security needs fewer than n/3 corruptions; honest majority alone gives this only for semi-honest adversaries (or statistical security with a broadcast channel).
- symmetric-encryption-block-ciphers.md, Q4 explanation: "the EFF's Deep Crack machine brute-forced a DES key in 22 hours in 1998". As I recall, Deep Crack alone took about 56 hours in 1998; the roughly 22-hour result was in January 1999, combined with distributed.net. Please verify.
- symmetric-encryption-block-ciphers.md, Q2 explanation: "2^128! possible permutations" should read (2^128)!. The reasoning about which (m, c) pairs are reachable is also muddled, though the conclusion (false) is right.
- threshold-cryptography.md, Core Idea: "cryptocurrency custody (multi-sig wallets)". On-chain multisig uses several separate keys and is distinct from threshold signatures. The new misconception bullet states this distinction; it does not contradict the Core Idea's broader point but readers may notice the tension.
- threshold-cryptography.md, Explainer: Schnorr partial signatures "sum to the correct full signature". With Shamir shares they must be weighted by Lagrange coefficients (the previous paragraph says so), and nonce generation needs care in practice.
- threshold-cryptography.md, Explainer: names Fireblocks and Coinbase as production deployments of proactive security. Not verified.
- verifiable-computation.md, Explainer: "exponentially long proofs can be verified by sampling". The PCP theorem gives polynomial-length proofs; the exponential-length construction is an earlier, weaker result.
- zero-knowledge-proofs.md, Q2 explanation and Explainer: GMW dated 1987. The paper appeared at FOCS 1986 (journal version 1991). Please verify.
