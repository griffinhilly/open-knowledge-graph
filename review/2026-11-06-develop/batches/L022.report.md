## Flags

### Suspected factual errors in existing text
- advanced-network-flow.md, Core Idea: "with O(E * sqrt(V)) for unit-capacity networks". The O(E sqrt V) bound holds for unit networks (each vertex has one incoming or one outgoing edge, as in bipartite matching). General unit-capacity networks give O(E * min(V^(2/3), E^(1/2))).
- advanced-network-flow.md, Q1 (short-answer) answer: "at most sqrt(V), since the paths are edge-disjoint in a unit graph". The standard argument uses vertex-disjoint paths in unit networks: V vertices / path length > sqrt(V) gives at most sqrt(V) paths. Edge-disjointness gives E/sqrt(V), not sqrt(V).
- advanced-network-flow.md, Q1 (short-answer) question: "O(E * sqrt(V)) time, which is optimal for maximum bipartite matching". Not known to be optimal; almost-linear-time max-flow algorithms (2022) beat it asymptotically.
- advanced-network-flow.md, Q0 option 1: "each push or relabel operation ... in O(1) time". A relabel scans the vertex's adjacency list, so it costs O(degree), not O(1).
- algorithmic-game-theory.md, Core Idea and Explainer: two-player Nash PPAD-completeness attributed to Daskalakis-Goldberg-Papadimitriou. DGP proved it for 3+ (initially 4) players; the two-player case is Chen-Deng (2006).
- algorithmic-game-theory.md, Q2 answer: "each agent's payment is independent of their own report". Only the Clarke pivot term is independent of the agent's report; the payment depends on the report through the chosen outcome.
- approximation-algorithms-advanced.md, Q0 explanation: "some instances (e.g., odd cycles) have LP_OPT = n/2 but OPT = ceil(n/2), with ratio approaching 2". That ratio tends to 1. The gap-2 example is the complete graph K_n (LP = n/2, OPT = n-1).
- approximation-algorithms-advanced.md, Q3 explanation: "Jain's iterative rounding for Steiner network" cited as a classic primal-dual example. Iterative rounding is an LP-rounding method, not primal-dual.
- bloom-filters.md, Q2 answer: "With 2 GB (16 bits/element), the rate drops to ~0.015% (1 in 7000)". At 16 bits/element with optimal k ~ 11, the rate is about 0.046% (about 1 in 2200). Also the intermediate expression "(1 - e^(-5.5))^5.5" should be "(1 - e^(-5.5/8))^5.5"; the final 2.2% is right.
- bloom-filters.md, Q0 explanation: "doubling to k = 14 ... roughly tripling the false positive rate". Computed: 0.82% -> about 1.9%, roughly 2.3x.
- communication-complexity.md, Core Idea: "only O(1) randomized bits" for equality holds for public-coin protocols; private-coin needs Theta(log n). The Explainer's paragraph mixes "shared randomness" with an O(log n) total.
- communication-complexity.md, Q1 (true-false): "estimating the number of distinct elements ... requires Omega(n) space", keyed true. The disjointness bound applies to exact counting; approximate distinct counting uses far less space (the explanation itself says so). The question wording makes the true key wrong.
- communication-complexity.md, Explainer: Kalyanasundaram-Schnitger / Razborov proof described as "information-theoretic arguments". Those proofs are combinatorial (corruption/discrepancy-style); the information-theoretic proof is Bar-Yossef, Jayram, Kumar, Sivakumar (2002).
- concentration-inequalities-algorithmic.md, Q4 explanation: "Chebyshev would require O(m) overhead". To get failure probability 1/m, Chebyshev needs deviation about sqrt(m) standard deviations, so the overhead is about sqrt(m), not m.
- derandomization-techniques.md, Q0 explanation: "randomized MAX-SAT 7/8-approximation". The 7/8 random-assignment bound is for MAX-3SAT with exactly three literals per clause (the Explainer says MAX-3SAT).
- derandomization-techniques.md, Q2: attributes "circuits of size 2^(epsilon n) for a function in E implies BPP = P" to Nisan-Wigderson. NW needed average-case hardness; the worst-case version is Impagliazzo-Wigderson (1997), built on NW.
- expander-graphs.md, Q1 explanation: Marcus-Spielman-Srivastava "winning the Polya Prize" for the Ramanujan result. Uncertain; their Polya Prize (2014) is usually cited for the Kadison-Singer work. Worth checking.
- exponential-time-hypothesis.md, multiple serious errors:
  - Core Idea and Explainer define SETH as a bound of 2^((1 - epsilon) k n). Standard SETH: for every epsilon > 0 there is k such that k-SAT on n variables cannot be solved in 2^((1 - epsilon) n) time. There is no factor k in the exponent.
  - Core Idea lists 3-SUM and all-pairs shortest paths as explained by ETH/SETH. Both have their own separate conjectures; neither is known to be SETH-hard. LCS and edit distance are SETH-hard.
  - Q0 explanation reasoning follows the wrong SETH definition; option 1 ("subexponential-time algorithm for k-SAT") is not what refuting SETH gives.
  - Q1 explanation: ETH is about 3-SAT; "equivalently, all k-SAT with unbounded k" is wrong. 2-SAT is linear time, not O(n^2).
  - Q2 answer: claims a reduction from 3-SAT to 3-SUM under SETH, concluding "3-SUM requires O(n^2)" (should be Omega, and no such SETH reduction is known).
  - Q3: "Fine-Grained Complexity Conjecture (FGC)" appears invented.
  - Explainer: an O(2^(0.99 n)) 3-SAT algorithm does not contradict ETH (3-SAT already has ~1.3^n algorithms). The paragraph conflates ETH and SETH.
  - Recommend a rewrite of this file.
- external-memory-algorithms.md, Q0 option 0: "log_{M/B}(N/M) = log_{M/B}(N/B) - 1 + log_{M/B}(B/M)". The identity is log_{M/B}(N/M) = log_{M/B}(N/B) - 1; the extra term is wrong (it would subtract another 1).
- fft-polynomial-multiplication.md, Explainer: "O(n log n), an exponential improvement over the O(n^2)". n log n vs n^2 is a polynomial (near-linear-factor) improvement, not exponential.
- fft-polynomial-multiplication.md, Explainer: FFT "essential for ... computational geometry (polygon area, point-set diameter)". Polygon area is a linear-time sum without FFT; these examples look wrong.
- fibonacci-heaps-amortized-analysis.md, Q4 explanation: "pairing heaps, which match the bounds empirically". Pairing heaps do not have O(1) amortized decrease-key (Fredman's lower bound is Omega(log log n) for that model); the Explainer's "similar empirical performance" is fine.

- fixed-parameter-tractability-advanced.md:
  - Explainer: "k-Clique is FPT (by brute force ...)". k-Clique is W[1]-complete and believed not FPT (parameterized-complexity.md says this correctly).
  - Explainer: "Not all FPT problems kernelize". A decidable problem is FPT if and only if it has a kernel; the open question is polynomial kernels.
  - Q2: Clique used as the example of no polynomial kernel. Kernel lower bounds are meaningful for FPT problems (e.g. k-Path); for W[1]-hard Clique, no kernel at all exists unless FPT = W[1]. The explanation also attributes the composition framework conclusion to k-Clique.
  - Core Idea and Q3: "rank-based arguments for kernel lower bounds" via linear independence of instance families. Standard kernel lower bounds use OR/AND-composition and cross-composition (Bodlaender et al.; Fortnow-Santhanam; Dell-van Melkebeek). The Q3 answer looks invented.
  - Q1: iterative compression "branches over subsets T of S with |T| = k"; it branches over all subsets of S (2^(k+1) choices). "Iterative compression was discovered for Feedback Vertex Set": it was introduced by Reed, Smith and Vetta for Odd Cycle Transversal (2004). The 3^k bound for FVS via compression is doubtful (deterministic compression bounds were 5^k, later about 3.6^k).
- las-vegas-vs-monte-carlo.md, Q2 explanation: "at least one gives a definitive answer each round". Each round gives a definitive answer with probability at least 1/2, not certainly.
- linear-programming-algorithms.md, Q1 answer: "The simplex method's per-iteration cost is much lower (O(n) for a pivot)". A tableau pivot costs O(mn); revised simplex costs less but not O(n) in general.
- link-cut-trees.md:
  - Core Idea: "Link-cut trees achieve O(m log n) total time for max-flow algorithms". Dinic's algorithm with dynamic trees runs in O(mn log n) total; O(m log n) is per blocking-flow phase (as the Explainer says).
  - Q2 answer: "Dinic's algorithm with O(n^2) blocking flow phases". Dinic has at most n - 1 phases.
  - Core Idea: preferred paths described as "heavy paths chosen dynamically". Preferred paths follow the most recent access; heavy paths appear only in the analysis.
- online-algorithms-competitive-analysis.md:
  - Explainer: "the randomized marking algorithm achieves competitive ratio H_k ... and this is tight". Marking achieves 2H_k - 1 (about 2 ln k). H_k is the lower bound, met by other algorithms (McGeoch-Sleator partition; Achlioptas-Chrobak-Noga).
  - Q3: lookahead claim. For paging, any fixed finite lookahead does not improve the deterministic competitive ratio, since the adversary can repeat each request L times. The paging example in the explanation is wrong; the online matching claim is unsupported.
- parallel-algorithms-pram.md, Explainer: "the models are polynomially equivalent but the constant factors in depth differ". The EREW/CRCW gap is up to a logarithmic factor in depth (the text itself shows OR: O(1) vs Omega(log n)), not a constant.
- parameterized-complexity.md:
  - Q3 (true-false, keyed true): "no polynomial-time algorithm can produce a kernel with (2-epsilon)k vertices unless the polynomial hierarchy collapses". Known vertex-count lower bounds for vertex cover kernels come from hardness of approximation under P != NP (e.g. no 1.36k-vertex kernel) or UGC (2 - epsilon). The PH-collapse result (Dell-van Melkebeek) is about O(k^(2 - epsilon)) bits/edges.
  - Q3 explanation: "Buss kernelization produce[s] a kernel with at most 2k vertices". Buss's rule gives O(k^2) vertices; 2k comes from crown reduction or the LP (Nemhauser-Trotter) approach.
  - Explainer: "C(10^6, 30) ... a number with 160 digits". It is about 4 x 10^147 (148 digits). Q0's "C(10^6, 20) ~ 10^99" is about 4 x 10^101.
- pcp-theorem-hardness-of-approximation.md:
  - Explainer: Set Cover "(1 - epsilon) ln n" listed among "Hastad's seminal 1997 results". That result is Feige (1998), under a stronger assumption, and Dinur-Steurer (2014) under P != NP.
  - Q2 answer: "Each iteration roughly squares the fraction of violated constraints (from delta to ~delta^(1/2) ...)". Dinur's step roughly doubles the gap (the Explainer says this correctly); the answer is garbled.
  - Q4 explanation: UGC "also inspired Dinur's combinatorial approach to gap amplification". Unsupported.
  - Core Idea: "without it, we would have no way to prove that certain approximation ratios cannot be beaten". Some inapproximability results (e.g. general TSP) predate PCP and do not need it.
- polynomial-identity-testing.md:
  - Q2 answer: "Edmonds defined the Tutte matrix ... He proved that G has a perfect matching iff det(T) is not identically zero". Tutte (1947) defined the matrix and proved this; Edmonds (1967) noted the bipartite determinant connection; Lovasz (1979) gave the randomized algorithm. The Core Idea's "Edmonds's reduction ... (via the Tutte matrix)" has the same issue.
  - Q2 answer and Explainer: "This gives a co-RP algorithm for perfect matching". A nonzero determinant certifies a matching, so the error is one-sided on the "no" side for a "yes" instance: the algorithm is RP for perfect-matching existence.
  - Q3 option 1: "NEXP does not have polynomial-size arithmetic circuits". Kabanets-Impagliazzo's alternative is NEXP not in P/poly (Boolean circuits), as the explanation says.
- probabilistic-method.md:
  - Q0 explanation: "the 2^(k/2) lower bound has only been improved by a constant factor (to 2^(k/2) * sqrt(2) by Sah in 2023)". The constant-factor improvement of the lower bound is Spencer's (1975, via the Local Lemma, factor 2). The 2023 breakthrough (Campos-Griffiths-Morris-Sahasrabudhe) and Sah's 2020 work improved the upper bound.
  - Q1: asks which step is the alteration for the bound alpha(G) >= sum 1/(d(v)+1) (Caro-Wei), but the keyed alteration argument gives n^2/(4m). Caro-Wei comes from the random-permutation greedy argument, which is option 2, a distractor. Question and key are mismatched.
  - Explainer: "alpha(G) >= n/(2d_avg), the Turan bound". The Turan bound is n/(d_avg + 1); n/(2 d_avg) is the weaker alteration bound.
  - Q4 explanation: "For k = 2*log_2(n) + 1 ... this quantity is less than 1". With 2^k about 2n^2, (1 - 2^(-k))^(n-k) is close to 1, so the bound fails. The argument works for k around log_2 n - 2 log_2 log_2 n (n about k^2 2^k).
  - Explainer: "No explicit construction achieves more than 2^(c*sqrt(k*log k))". Possibly outdated given recent explicit Ramsey graph constructions (Cohen 2016; Li 2023); worth checking.
- property-testing.md:
  - Q1 (true-false, keyed true): "every graph property expressible in first-order logic is testable" in the dense model. Alon-Fischer-Krivelevich-Szegedy showed testability for first-order properties with an exists-forall quantifier prefix; some forall-exists properties are not testable. The key is wrong.
  - Q2 answer: claims triangle-freeness needs Theta(n^(1 - delta)) queries for one-sided testing. Triangle-freeness has a one-sided tester with query complexity depending only on epsilon (via the triangle removal lemma). The example is wrong.
  - Q3 explanation: "testing whether a bounded-degree graph is connected requires Omega(sqrt(n)) queries". Connectivity is testable in the bounded-degree model with query complexity independent of n (Goldreich-Ron). Bipartiteness is the right sqrt(n) example.
  - Explainer: "a function's distance from linearity equals the fraction of its Fourier weight outside the linear characters". The distance is (1 - max Fourier coefficient)/2; the stated equality is not the standard relation.
- ptas-and-fptas.md:
  - Q1 explanation: "Bin packing and Euclidean TSP have PTAS". Bin packing has no PTAS unless P = NP (3/2 is a lower bound); it has an asymptotic PTAS. The Explainer's "bin packing (strongly NP-hard) does not [have an FPTAS]" is true but the PTAS claim is wrong.
  - Core Idea, Q0 and Explainer: knapsack FPTAS "DP table has dimensions n x (n/epsilon), giving O(n^2/epsilon)". With max scaled profit n/epsilon, the profit-indexed table has n x (n^2/epsilon) entries, giving the standard O(n^3/epsilon); O(n^2/epsilon)-type bounds need refinements.
- quantum-algorithms-beyond-shor.md:
  - Q0 explanation: "This quadratic speedup is conjectured optimal: the quantum query lower bound (by Bennett et al.) shows Omega(sqrt(n)) queries are necessary". It is proven optimal (BBBV 1997), as the Explainer says; "conjectured" contradicts the same sentence.
  - Q2 stem: "Shor's and Grover's algorithms which offer unconditional speedup". Grover's query speedup is unconditional; Shor's speedup over classical factoring is not, since no classical lower bound for factoring is known.
  - Explainer: phase estimation used "in variational algorithms (to estimate energies)". Variational algorithms such as VQE estimate energies by direct repeated measurement, avoiding phase estimation.
  - Core Idea: BQP "likely contains problems outside P and NP". Factoring is in NP; containment of problems outside NP is supported only by oracle separations.
- random-sampling-techniques.md:
  - Q0 explanation contains a drafting artifact: "(j-1)/(n-1) — wait, more carefully:" followed by a corrected computation. The first expression is wrong and the "wait" text should be removed.
  - Q1 (true-false, keyed true): "This reweighting always produces an unbiased estimator". It needs q > 0 wherever p * f is nonzero, as the explanation says; "always" in the stem makes the key shaky.
