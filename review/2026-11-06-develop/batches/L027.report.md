## Flags

- separation-logic-advanced.md, Explainer and Q4: "the deny condition specifies actions the environment is forbidden from taking". Deny-guarantee (Dodds, Feng, Parkinson, Vafeiadis) splits rely/guarantee interference into transferable permissions, so threads that are created and joined dynamically can be handled. A "deny" permission forbids everyone, including the holder, from doing an action. The file's description, which treats deny as a third, separate condition on the environment, is a misreading. The Q4 phrase "Rely-guarantee specifies lower bounds on interference" also looks garbled.
- separation-logic-advanced.md, Explainer: "It's higher-order because the definition quantifies over other predicates and uses recursion." The list(x, len) predicate shown does not quantify over predicates. It is an inductive predicate, and inductive predicates are also used in first-order separation logic.
- separation-logic-advanced.md, Explainer: "{list(x) * credits(10)} C {list(x) * credits(0)} means C ... using exactly 10 credits". The answer to Q3 says "at most". Credits bound cost from above, so "exactly" is wrong.
- separation-logic.md, Q3 explanation: "With n pointers, this creates 2^(n choose 2) cases." Aliasing is transitive, so the number of possible alias patterns is the number of partitions of n items (the Bell number), not 2^(n choose 2).
- session-types.md, Explainer and Q4: "Each channel endpoint must be used exactly once". In session types, an endpoint is owned linearly and is used once per stage of its type. It can carry many messages in sequence. As worded, the sentence suggests one use in total.
- smt-solving-theories.md, Q3 (true-false, answer true): "SMT solvers can always decide the satisfiability of quantifier-free formulas in supported theories." The file's own explanation says quantifier-free nonlinear integer arithmetic is undecidable, and Z3 supports it. As stated, the answer should be false, or the question should be narrowed. The same explanation's "LRA is in polynomial time" holds only for conjunctions of literals. With Boolean structure, the problem is NP-complete.
- smt-solving-theories.md, Explainer: "a theory conflict clause -- a minimal unsatisfiable subset". Solvers return an unsatisfiable subset (an explanation). It is often small, but it is not necessarily minimal.
- symbolic-execution-advanced.md, Core Idea and Explainer: TriforceAFL is listed as a whole-system symbolic execution tool. TriforceAFL is an AFL-based fuzzer for kernels, run under QEMU. It does not do symbolic execution.
- symbolic-execution-advanced.md, Core Idea: "These techniques reduce path explosion from exponential blowup to manageable scale". This overstates the result. They mitigate path explosion; they do not remove the exponential worst case.
- symbolic-execution-advanced.md, Explainer: "Tools like KLEE (Stanford) use coverage guidance to systematically explore all branches without exhaustive enumeration". This is an overclaim. Coverage heuristics prioritize paths and do not guarantee that every branch is explored.
- symbolic-execution.md, Explainer: SAGE "having found roughly one-third of all security bugs discovered during Windows 7 development". The commonly cited claim is narrower: about one-third of the bugs found by file fuzzing during Windows 7 development.
- symbolic-execution.md, Core Idea: "Symbolic execution systematically explores all program paths". This contradicts the file's own point about path explosion. In practice, tools explore a subset.
- termination-analysis.md, Explainer: "Transition invariants ... show that the transitive closure of the loop's transition relation is well-founded." The technique shows that the transitive closure is contained in a finite union of well-founded relations (disjunctive well-foundedness). The quoted wording restates termination itself rather than the method.
- termination-analysis.md, Core Idea: "automatically proving termination for the vast majority of practical loops". This statistic is unsupported.
- weakest-precondition.md, Q4: this question frames wp for loops via invariants that give partial correctness. Dijkstra's wp also needs a variant (ranking function) for termination. The answer omits this, though it is not strictly wrong as an outline.
- Prerequisite: smt-solving-theories -> symbolic-execution (soft). The Core Idea and Explainer depend on SMT queries for path feasibility, but SMT solving is not listed as a prerequisite.
