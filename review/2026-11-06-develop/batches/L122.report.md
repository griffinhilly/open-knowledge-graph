## Flags

- abstract-syntax-trees.md, Q2 explanation: "semantically equivalent expressions produce identical ASTs". Too strong: `a + b` and `b + a` are semantically equivalent but have different ASTs. The claim holds for grouping punctuation only.
- ad-hoc-polymorphism-overloading.md, Core Idea and Q3: overload selection is "at compile-time" as a "defining property". Haskell type classes (cited in the Explainer) can resolve to a dictionary passed at runtime for polymorphic code, so compile-time selection is typical of C++/Java overloading, not a definition of ad hoc polymorphism.
- alias-analysis.md, Q2: marked answer says the compiler blocks the optimization on may-alias. Option A (insert a runtime overlap check and version the loop) is what GCC and LLVM commonly do for vectorization, so the item has two defensible answers.
- alias-analysis.md, Core Idea: lists "strength reduction" as enabled by alias analysis. Strength reduction does not normally depend on alias information; load/store reordering, redundant load elimination and LICM do.
- array-subscript-optimization.md, Explainer para 3 and Q2 explanation: "Data dependence analysis confirms these transformations are safe". Strength reduction of address arithmetic is justified by induction-variable algebra, not by dependence analysis. Q1 explanation calls option D "constant folding"; it is closer to loop-invariant code motion.
- bytecode-and-vm-design.md, Q4: answer `false` to "AOT native code typically outperforms JIT-compiled bytecode" plus the explanation ("faster than anything static analysis can produce") overstate a contested claim. Explainer para 1 says bytecode is "designed not for further compilation", which conflicts with the JIT discussion later in the same file.
- code-optimization.md, Q2: "preserving observable behavior is an absolute constraint ... no exceptions". Programs with undefined behavior and opt-in flags such as -ffast-math can legitimately produce different output. Q5 premise ("every compiler optimization must be justified by a dataflow analysis") is too strong: peephole algebraic rewrites like x*2 -> x<<1 need none.
- compiler-bootstrapping.md, Q2 and Explainer para 4: says binaries N+1 (built by old binary N) and N+2 (built by N+1) should be identical. They are built by different compilers and generally differ. The standard check (e.g. GCC's stage2 vs stage3 compare) is that N+2 and N+3 match, both built by compilers from the same source.
- compiler-bootstrapping.md, Q5 explanation and Explainer: "GCC (from Pastel)" / "originally bootstrapped from a Pastel compiler". Stallman considered adapting the Pastel compiler but GCC was written in C and first built with existing C compilers. Likely wrong.
- compiler-bootstrapping.md, Core Idea: "A bootstrap compiler is a compiler written in its own language". That defines a self-hosting compiler; "bootstrap compiler" usually means the initial compiler used to break the circularity.
- compiler-bootstrapping.md, Q4 has grammar errors ("you is expected", "can seldom compile") and Explainer para 2 says "you write a C compiler for a subset of X", which should read a compiler for a subset of X written in C.
- compiler-error-recovery.md, Core Idea: "phrase-level recovery (skip to known safe states)". Skipping to safe states is panic mode; phrase-level recovery is local insertion/deletion/replacement, as the file's own Explainer and Q3 say.
- constraint-based-type-checking.md, Q2 explanation and Explainer para 4: new constraint forms (subtyping, trait bounds) can be added "without rewriting the solver" / "solver can often handle these without modification". Subtyping and type-class constraints need solver support beyond unification. Explainer also lists TypeScript as constraint-based; TypeScript's inference is mostly local and bidirectional. Core Idea's "clearer error messages" is contested: whole-program inference is known for errors reported far from the cause. Q1 explanation's "+ requires the same numeric type, so α = int" holds for OCaml but not Haskell, which infers `Num a => a -> a`.
- context-free-grammars-compiler-design.md, Explainer para 3: "Only a context-free grammar can capture this." More powerful formalisms can too; the point is that regular expressions cannot. Para 4: left factoring is said to "avoid ambiguity"; it removes the need for backtracking/lookahead in LL parsing, not ambiguity.
- control-flow-graphs.md, Q2: "a conditional branch always produces exactly two outgoing edges" marked true. If both targets are the same block there is one successor. Explainer para 3 defines back edges as edges "that point backward to an earlier block"; the standard definition is an edge whose target dominates its source.
- dataflow-analysis.md, Explainer para 4: "loops requiring at most as many iterations as the nesting depth". The known bound (for rapid frameworks visited in reverse postorder) is loop-connectedness plus two passes, which is not nesting depth, and does not hold for all frameworks. Also "finite lattice" where finite height is the actual requirement.
- dead-code-elimination.md, Q4 explanation: "a block is unreachable if it has no predecessors other than itself"; Explainer para 3: "basic blocks with no predecessors". Unreachability is lack of a path from the entry; a cycle of blocks unreachable from entry has predecessors. Q4 stem is garbled ("seldom executed during any test run").
- dependent-types-programming.md, Explainer para 2: "In the simply-typed lambda calculus, you have terms that depend on terms ... and types that depend on types (generic/parametric polymorphism)". STLC has only terms depending on terms; parametric polymorphism is terms depending on types (System F). Q4 explanation repeats that generics are "types depending on types". Q4's claim that dependent types are not a generalization of generics is contested: in a full dependent theory (e.g. Calculus of Constructions) Π-types over a universe subsume ∀.
- dependent-types-programming.md, Explainer para 1: "n is a natural number known at compile time". The index can be a variable whose value is known only at runtime; the checker reasons about it symbolically.
